# 投递记录筛选面板设计稿

## 背景

投递记录管理页已经切换为表格视图，但用户希望进一步收敛信息密度与交互方式。当前版本仍有几个问题：

- `来源站点` 这一列占用了横向空间，但优先级不够高；
- `链接` 列目前宽度偏大；
- 列头里的排序与筛选图标过于显眼，表头显得偏重；
- 列头承担了过多交互职责，不够干净；
- 链接虽然作为字段展示，但用户仍希望鼠标移上去后单击即可直接打开。

这一轮目标是让表头更轻、更像标准数据表，同时把筛选能力集中到一个统一入口。

## 目标

- 去掉 `来源站点` 列。
- 将 `链接` 列宽缩小到当前的大约一半，并保持固定宽度。
- 列头只保留更小的排序图标，且整块列标题都可点击排序。
- 去掉列头中的筛选图标。
- 在表格右上角新增统一的 `筛选` 按钮，点击后弹出筛选面板。
- 浏览态下，链接列文本可直接点击打开；编辑态下仍是普通文本输入框。

## 非目标

- 不调整投递记录 schema。
- 不修改新建投递记录页行为。
- 不恢复顶部独立筛选框。
- 不引入多列复合排序、高级条件组合或保存筛选方案。
- 不修改 CSV 导入导出逻辑。

## 用户体验

### 表格列

表格列调整为：

- 公司
- 岗位
- 链接
- 状态
- 投递日期
- 工作地点
- 备注
- 操作

`来源站点` 整列移除，不再出现在浏览态或编辑态表格中。

### 链接列

浏览态：

- 仍显示为链接文本；
- 列宽固定；
- 超出宽度时截断；
- 鼠标移上去有链接态反馈；
- 单击即可直接打开链接。

编辑态：

- 这一格直接切换成普通文本输入框；
- 用户可以像编辑其他字段一样直接修改链接。

### 排序

每个可排序列头只保留一个更小的排序图标。  
但排序触发区域不只在图标本身，而是整块列标题都可点击。

点击顺序为：

- 第一次：升序
- 第二次：降序
- 第一版不要求第三次回到“无排序”

### 筛选

表格右上角放一个独立 `筛选` 按钮。点击后弹出一个统一筛选面板。

面板内按字段提供输入项：

- 公司
- 岗位
- 链接
- 状态
- 投递日期
- 工作地点
- 备注

已生效的筛选条件应以轻量标签的形式显示在筛选按钮附近，方便用户快速看到当前筛选状态。

## 交互设计

### 筛选面板

筛选按钮点击后：

- 弹出一个小面板；
- 面板中可直接输入或选择筛选值；
- 支持清空所有筛选；
- 点击面板外区域时关闭。

筛选面板关闭后，已输入的条件仍保留并继续生效。

### 链接打开

浏览态下，链接列中的文本本身就是点击目标，而不是额外按钮。  
为避免编辑态冲突：

- 仅浏览态渲染为可点击链接；
- 编辑态改为输入框后，不再具备直接打开行为。

## 视觉设计

### 表头

- 去掉筛选图标后，列头信息层次应更轻；
- 排序图标尺寸缩小一档；
- 整个列头 hover 时有轻反馈，暗示可点击排序；
- 当前排序列可用颜色或方向区分。

### 筛选按钮与标签

- `筛选` 按钮应是一个轻量次级按钮；
- 已生效筛选条件标签放在它附近，避免占据整行；
- 标签可简短展示，如 `公司: 字节`、`状态: 面试`。

### 链接列

- 使用固定列宽；
- 文本超长省略；
- hover 时显示链接色或下划线；
- 保持整行表格的视觉整洁。

## 架构建议

### 筛选状态

继续沿用按字段存储筛选值的方式，但 UI 入口从“列头图标/顶部输入框”切到“统一筛选面板”。

建议新增：

- `isFilterPanelOpen`
- `columnFilters`

现有 `sortState` 可以继续沿用，只需调整触发方式。

### 表头点击

建议将 `<th>` 内部包裹一个可点击容器，用于整块触发排序，而不是只点击小图标。

### 链接列宽

通过 CSS 固定 `链接` 列宽，不让其随内容扩张。  
如果小屏下表格过宽，仍由外层表格容器提供横向滚动。

## 测试要求

至少覆盖以下场景：

- `来源站点` 列不再渲染。
- 表头点击即可触发排序，而不依赖单独图标点击。
- 列头中不再出现筛选按钮。
- 点击右上角 `筛选` 按钮后，出现统一筛选面板。
- 输入筛选条件后，表格结果正确过滤。
- 浏览态下链接列渲染为可点击链接。
- 编辑态下链接列仍是普通文本输入框。

## 验收标准

- 表格中不再出现 `来源站点` 列。
- `链接` 列比当前更窄，且固定宽度。
- 列头不再出现筛选图标。
- 排序图标更小，整块列标题可点击排序。
- 表格右上角存在统一 `筛选` 按钮。
- 点击 `筛选` 后出现统一筛选面板。
- 浏览态下鼠标移到链接文本并单击即可打开链接。
- 编辑态下链接仍然可直接修改。

## 风险

- 去掉 `来源站点` 后，若用户仍需判断来源，信息可能更多依赖链接字段本身。
- 链接列过窄时，省略过多可能降低可读性，需要在宽度和可识别度之间取平衡。
- 统一筛选面板如果字段太多，面板高度会增加，需要控制布局密度。

## 结论

这一轮应把投递记录表格收敛成“表头专注排序、筛选集中管理、链接字段回归字段本身”的形态。这样可以明显减少列头噪音，同时保留筛选和打开链接的效率。
