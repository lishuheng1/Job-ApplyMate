# 投递记录行内编辑设计稿

## 背景

投递记录列表已经从大卡片压缩成更紧凑的单行结构，但当前交互仍然有两个明显问题：

- 每一行右侧仍使用文字按钮，信息密度不够高；
- 点击 `编辑` 后仍然依赖右侧单独编辑卡片，操作路径偏长，也会让列表与编辑区视线来回跳转。

同时，新建投递记录页在保存成功后会自动关闭窗口，这与用户最新希望的“保存后仍留在页面，由自己决定是否关闭”不一致。

这一轮只收敛交互与布局，不调整投递记录的数据结构、导入导出策略或状态流。

## 目标

- 将投递记录列表每一行右侧操作改为：`打开链接` + `编辑` 图标 + `删除` 图标。
- `编辑` 和 `删除` 使用轻量线性 SVG 图标，不再显示中文按钮文字。
- 点击 `编辑` 后在当前这一行下方直接展开编辑区，而不是依赖右侧编辑卡片。
- 新建投递记录页保存成功后不再自动关闭窗口，而是在保存按钮附近显示持续可见的 `已保存` 提示。

## 非目标

- 不新增字段，不修改 `ApplicationRecord` schema。
- 不调整投递记录的预填逻辑、重复判断或保存消息类型。
- 不新增批量操作、排序方式或统计视图。
- 不修改 CSV 导入导出行为。
- 不重新设计整个设置页布局，只聚焦投递记录分区。

## 用户体验

### 列表行操作

每一行右侧操作固定为：

- `打开链接`
- `编辑` 图标按钮
- `删除` 图标按钮

其中：

- `打开来源链接` 文案统一缩短为 `打开链接`；
- `编辑` 使用线性铅笔图标；
- `删除` 使用线性垃圾桶图标；
- 图标按钮需要有清晰的 hover、focus-visible 和禁用态；
- 图标本身不承担解释文字，但应保留 `aria-label` 方便可访问性和测试定位。

### 行内编辑

点击 `编辑` 后，不再把内容带到右侧卡片，而是在当前记录行下方原位展开编辑表单。

编辑区保留第一版已有的核心字段：

- 公司名
- 岗位名
- 来源站点
- 状态
- 来源链接
- 投递日期
- 工作地点
- 备注

编辑区只在当前选中行下方展开一次。用户保存或取消后，编辑区收起，列表恢复紧凑状态。

### 新建页保存反馈

新建投递记录页保存成功后：

- 不再自动关闭窗口；
- 在保存按钮附近显示 `已保存`；
- 成功提示保持可见，直到用户继续修改、再次保存或手动关闭窗口。

提示应靠近保存按钮，而不是放在页面顶部，避免用户误以为窗口已经执行完关闭流程。

## 交互设计

### 行内编辑展开方式

列表默认保持“单行一条”的浏览态。  
当用户点击某一行的 `编辑` 图标时：

1. 当前行进入选中态；
2. 在该行下方插入一块展开式编辑区；
3. 用户可直接在该处修改并保存；
4. 保存成功后收起编辑区，并给出 `投递记录已更新` 提示；
5. 点击 `取消` 时收起编辑区，不改动原记录。

### 右侧编辑区处理

本轮移除投递记录分区内原有的右侧编辑卡片，不再保留“双栏列表 + 编辑侧栏”结构。  
列表区域改为单列流式布局，更适合当前“以列表浏览为主、按需展开单条编辑”的模式。

### 新建页成功提示

保存按钮附近显示持续可见的成功态，例如：

- 左侧为 `已保存` 文案；
- 右侧仍保留保存按钮，允许用户继续修改后再次保存。

这意味着成功提示应是表单动作区的一部分，而不是一次性 toast。

## 视觉设计

### 操作区

每一行操作区从“多个次级文字按钮”收敛为：

- 一个文字链接按钮 `打开链接`
- 两个方形图标按钮

图标按钮应尺寸统一、边框轻、hover 有浅底色反馈，不做过强阴影。

### 行内编辑区

展开后的编辑区可采用比列表行稍浅的背景块，与浏览态分层，但不要重新回到大卡片堆叠的视觉重量。  
建议通过：

- 轻边框
- 柔和背景
- 紧凑字段排布

来保证可编辑性与列表密度平衡。

## 架构建议

### 列表与编辑合并

`ApplicationRecordsSection` 当前已经用 `editingId` 与 `draftRecord` 管理编辑状态，这套状态可以继续沿用，不需要重构消息流。  
本轮只调整渲染位置：

- 从“右侧 editor 容器渲染”
- 改为“在匹配 `editingId` 的那一条记录后渲染”

### 图标实现

直接在组件内使用内联 SVG 即可，不需要引入额外图标库。  
这样更轻，也避免新的依赖。

### 新建页

保留现有表单与保存逻辑，只移除 `window.close()`，并把成功提示移动到保存按钮附近的动作区。

## 测试要求

至少覆盖以下场景：

- 新建页保存成功后不会调用关闭窗口逻辑。
- 新建页保存成功后在按钮附近渲染 `已保存`。
- 列表行操作区渲染 `打开链接`、编辑图标按钮、删除图标按钮。
- 点击 `编辑` 图标后，当前行下方展开编辑区。
- 点击 `取消` 后，行内编辑区收起。
- 点击 `保存修改` 后，仍走原有更新消息流。

## 验收标准

- 投递记录列表每一行右侧显示 `打开链接`、编辑图标、删除图标。
- `编辑` 与 `删除` 不再使用中文文字按钮。
- 点击 `编辑` 后在该行下方直接展开编辑区。
- 不再显示右侧独立编辑卡片。
- 新建投递记录保存成功后窗口保持打开。
- 保存按钮附近会持续显示 `已保存`，由用户自己决定何时关闭窗口。

## 风险

- 行内编辑会让单条记录临时变高，需要控制展开区的视觉层级，避免重新形成“大卡片瀑布”。
- 图标按钮如果过小，虽然更省空间，但可能损失可点击性，需要保证足够 hit area。
- 去掉右侧编辑区后，窄屏与宽屏的布局逻辑要重新平衡，避免一行信息和展开表单都过于拥挤。

## 结论

这一轮应把投递记录从“能用但有点绕”收敛到“浏览更紧凑、编辑更就地、保存反馈更符合预期”。通过图标操作、行内展开编辑和新建页常驻成功提示，可以明显减少用户来回跳转与误解保存结果的成本。
