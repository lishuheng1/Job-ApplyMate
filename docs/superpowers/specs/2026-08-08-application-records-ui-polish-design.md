# 投递记录界面微调设计稿

## 背景

投递记录第一版已经完成基础闭环：popup 提供 `新建投递记录` 与 `查看投递记录` 入口，新建页支持确认保存，设置页支持筛选、编辑和 CSV 导入导出。但在真实使用中，当前交互还存在几个明显的体验问题：

- 新建投递记录保存后仍停留在当前窗口，缺少更自然的结束动作；
- popup 顶部两个投递记录按钮尺寸偏小，悬浮时鼠标样式也没有和其他按钮保持一致；
- 设置页的投递记录列表仍以卡片形式铺开，在记录数量稍多时占用垂直空间过大。

这一轮不改动投递记录的数据模型、消息协议和业务边界，只收敛界面密度与操作反馈。

## 目标

- 新建投递记录保存成功后，立即提示“已保存”并关闭当前新建窗口。
- popup 顶部的 `新建投递记录` 与 `打开投递记录` 两个按钮在视觉和交互上更接近现有主按钮：点击区域更大，hover 时鼠标显示小手。
- 设置页中的投递记录列表从“卡片式堆叠”调整为“单行一条”的紧凑列表。
- 保留右侧编辑区，不把现有编辑能力改成表格内联编辑。

## 非目标

- 不调整投递记录字段集合。
- 不改变新建页的预填策略、重复判断和保存语义。
- 不改变设置页右侧编辑区的字段结构。
- 不新增统计视图、批量操作或更多筛选维度。
- 不修改 CSV 导入导出逻辑。

## 用户体验

### 新建页保存

用户在 `新建投递记录` 页面点击保存后，若保存成功：

- 先给出一次明确成功反馈，文案为 `已保存`；
- 随后立即关闭当前新建投递记录窗口；
- 不再停留在页面内展示持续性的成功状态。

由于用户已明确选择“保存后立刻关闭”，因此成功反馈应为短暂且不阻断的轻提示，而不是需要用户额外确认的对话框。

### popup 顶部按钮

popup 顶部右侧两个按钮维持上下排列，但需要做这几项微调：

- 增大按钮高度和左右内边距，提升点击命中面积；
- 字号和字重略微提升，减少“辅助按钮过小”的感觉；
- hover 时确保 `cursor: pointer` 生效，鼠标表现与当前 popup 里的其他按钮一致。

按钮仍然属于头部辅助操作区，不与下方主操作按钮混排。

### 记录列表

设置页 `投递记录` 标签中的左侧列表，从卡片式布局改为单行列表。每行应尽量在一屏内提供足够多的信息，但不要重新退化成难读的纯表格。

建议一行展示这些信息：

- 公司名
- 岗位名
- 状态
- 来源站点
- 投递日期
- 右侧操作：`编辑`、`打开链接`、`删除`

备注不再默认占据独立大块区域，完整备注继续放在右侧编辑区查看和修改。这样既能显著提高信息密度，又不会损失编辑能力。

## 范围

本设计涉及：

- `src/application-records/App.tsx` 的保存成功反馈与窗口关闭行为；
- `src/popup/App.tsx` 与 `src/popup/index.css` 中顶部投递记录按钮的文案、尺寸与 hover 样式；
- `src/options/ApplicationRecordsSection.tsx` 与 `src/options/index.css` 中投递记录列表的布局与样式；
- 对应测试更新。

本设计不涉及：

- `src/background/applicationRecords.ts` 的业务逻辑调整；
- 投递记录 schema 变更；
- 新增消息类型；
- 设置页标签结构调整；
- 右侧编辑区字段增删。

## 交互设计

### 保存成功后关闭窗口

新建页保存成功后应按以下顺序执行：

1. 保存请求成功返回；
2. 触发 `已保存` 提示；
3. 关闭当前窗口。

关闭前不需要再把页面切换到“保存成功”状态，也不需要保留表单内容。

### 顶部按钮命名

为了和当前用户表述保持一致，popup 里的第二个按钮建议统一显示为 `打开投递记录`，而不是 `查看投递记录`。  
这个调整不改变其真实动作，仍然是打开设置页并切到 `投递记录` 标签。

### 列表与编辑区关系

本轮仍保持“左侧列表 + 右侧编辑区”的双栏结构，只把左侧的单条记录从大卡片压缩为紧凑行。

点击某一行时：

- 进入右侧编辑区；
- 当前行应有选中态；
- 行内不直接展开编辑表单。

这样可以避免把大量字段重新塞回列表视图。

## 视觉设计

### 顶部按钮

按钮应从当前接近“标签 pill”的尺寸，调整到更接近紧凑次级按钮：

- 高度略增；
- 左右内边距增加；
- 文本字号从极小值提升一档；
- hover、focus-visible 与现有 `.button` 系列的交互反馈保持一致。

### 单行列表

左侧记录区改成列表行后，每一行建议使用如下视觉结构：

- 左侧主信息：公司名为第一视觉重点，岗位名次之；
- 中间辅助信息：状态、来源站点、投递日期；
- 右侧操作按钮；
- 行高控制在明显低于当前卡片高度的范围内。

列表行之间使用细边框、浅背景或 hover 高亮区分，不再使用大面积卡片阴影和多块 `dl` 信息面板。

## 架构建议

### 新建页

保留现有 `App.tsx` 表单结构，只在保存成功分支新增轻提示与 `window.close()` 收尾逻辑。

### popup

保留当前头部操作区结构，不改单独组件，只收敛：

- 文案；
- 尺寸；
- hover 样式；
- 光标样式。

### options

保留 `ApplicationRecordsSection` 的数据流和右侧编辑区，只重写左侧列表项的 DOM 结构和 CSS 类名，使其更适合单行信息布局。

## 测试要求

至少覆盖以下场景：

- 新建页保存成功后会触发关闭窗口逻辑。
- 新建页成功提示文案为 `已保存`。
- popup 中 `新建投递记录` 与 `打开投递记录` 按钮仍能正常渲染。
- 投递记录列表以单行布局渲染核心字段，而不是依赖旧卡片结构断言。
- 点击单行记录后仍可进入右侧编辑区。

## 验收标准

- 新建投递记录保存成功后，窗口会自动关闭。
- 用户能感知到一次明确的成功反馈，文案为 `已保存`。
- popup 顶部两个投递记录按钮比当前更大，hover 时鼠标显示小手。
- popup 顶部第二个按钮显示为 `打开投递记录`。
- 设置页投递记录列表不再以大卡片形式占用大量纵向空间。
- 左侧列表单行展示公司名、岗位名、状态、来源站点和投递日期。
- 右侧编辑区继续可用，编辑能力不回退。

## 风险

- 如果“已保存”提示完全依赖窗口内可见时长，立即关闭窗口后用户可能来不及读取，因此实现时需要选择足够轻但可感知的提示方式。
- 列表行压缩后，若字段过长，需妥善处理溢出和截断，避免行高重新膨胀。
- 若操作按钮在单行内排布过多，窄屏时容易挤压主信息，需要为小宽度做降级排版。

## 结论

这一轮应定位为投递记录第一版的界面收口，而不是功能扩张。通过“保存即关闭”“头部按钮更易点”“记录列表更紧凑”这三项微调，可以明显改善第一版的真实使用感受，同时不引入新的业务复杂度。
